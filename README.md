# RoboMaster EP — Grid SLAM และ DFS

ระบบสำรวจแผนที่แบบช่องด้วย RoboMaster EP หุ่นเริ่มโดยไม่มีข้อมูลกำแพงล่วงหน้า ใช้ ToF บน Gimbal สแกนและสร้างแผนที่ระหว่างวิ่ง ใช้ DFS เลือกทางใหม่และย้อนกลับเมื่อไม่มีทางไปต่อ

- **ToF:** วัดกำแพงเพื่อสร้างแผนที่ และตรวจด้านหน้าเพื่อชะลอ/หยุดก่อนชนระหว่างเดิน
- **Sharp ซ้าย–ขวา:** ใช้ PID Centering เพื่อปรับหุ่นให้อยู่กลางทางเดิน
- **Odometry และ yaw:** ประเมินตำแหน่งและรักษาทิศทาง โดยใช้กำแพงที่เคยวัดช่วยปรับตำแหน่ง

ใช้ Gimbal ติด ToF ไม่มี Gripper ไม่มีแผนที่กำแพงล่วงหน้า และไม่มีระบบจำลองหรือ fallback ไปใช้ข้อมูลจำลอง

## ติดตั้งและเริ่มงาน

ใช้ Python 3.8 และติดตั้ง dependencies ตาม `requirements.txt`:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

เชื่อมต่อเครือข่ายของหุ่นตามโหมด AP/STA ที่กำหนดใน `config/settings.yaml` แล้วรันบนเครื่องที่มีหน้าจอกราฟิกและ Tkinter:

```bash
python main.py
```

หน้าต่างมีปุ่มเลือกงาน ช่องตั้งค่าการเลี้ยว/คำสั่งเดิน/Calibration ปุ่มหยุดงาน และแผนที่ Grid ที่อัปเดตจากไฟล์แผนที่ระหว่างสำรวจทุก 0.4 วินาที สีฟ้าคือช่องที่สำรวจแล้ว สีส้มคือตำแหน่งหุ่น สีเขียวคือจุดเริ่ม และเส้นดำคือกำแพง การหยุดงานอาจรอคำสั่ง SDK ที่กำลังทำอยู่ให้จบก่อน

## พิกัดแผนที่และ settings

พิกัดช่องใช้ **`(row, column)`** ทั้งในโค้ด ภาพ และรายการ action:

- `row` เพิ่มจากล่างขึ้นบน ตามทิศหน้าเริ่มต้นของหุ่น
- `column` เพิ่มจากซ้ายไปขวา ตามทิศขวาเริ่มต้นของหุ่น
- ช่อง `(0,0)` อยู่ซ้ายล่างของภาพ
- จุดเริ่มต้นตั้งด้วย `map.start.row` และ `map.start.column`

ตัวอย่างแผนที่ 4 แถว × 3 คอลัมน์ มี 12 ช่อง:

```yaml
map:
  rows: 4
  columns: 3
  start:
    row: 0
    column: 0
```

```text
row 3    (3,0)  (3,1)  (3,2)
row 2    (2,0)  (2,1)  (2,2)
row 1    (1,0)  (1,1)  (1,2)
row 0    (0,0)  (0,1)  (0,2)
         col 0  col 1  col 2
```

ขนาดแผนที่กำหนดเฉพาะขอบเขต ไม่ได้กำหนดกำแพง หุ่นจะไม่เดินออกนอกขอบเขตแม้ ToF เห็นทางเปิด พิกัด odometry ที่วัดเป็นเมตรยังใช้ x/y ตาม SDK แยกจากหมายเลขช่อง row/column

| กลุ่ม settings | หน้าที่ |
| --- | --- |
| `robot` | โหมดเชื่อมต่อและเครื่องหมายคำสั่ง yaw |
| `map` | จำนวนแถว คอลัมน์ และช่องเริ่มต้น |
| `gimbal` | โหมดสแกน ความเร็ว move/recenter เวลาพัก และจำนวนรอบทดสอบ |
| `navigation` | ขนาดช่อง ความเร็วเดิน ระยะกันชน และเวลาพัก |
| `pid` | ค่าควบคุม Centering และ yaw |
| `sensors` | พอร์ต Sharp, ToF, อัตรารับข้อมูล และค่าตัวกรอง |
| `slam`, `scan_guard` | การประมาณตำแหน่ง ขีดจำกัดการสำรวจ และการตรวจข้อมูลระหว่างสแกน |
| `paths`, `calibration`, `telemetry`, `system` | ตำแหน่งไฟล์ สมการ บัฟเฟอร์ และเวลาของระบบ |

ค่าขณะนี้: ช่อง 60 ซม., เดินสำรวจ 0.28 m/s, ทดสอบหนึ่งช่อง 0.22 m/s, เลี้ยว 60°/s และจำกัดความเร็วแก้ด้านข้าง 0.08 m/s ค่าจริงอ่านจาก YAML ทุกครั้งที่เปิดโปรแกรม

## Workflow การสำรวจและ Gimbal

Workflow ต่อไปนี้ใช้ `gimbal.scan_mode: gimbal` ซึ่งเป็นค่าปัจจุบัน:

1. วางหุ่นกลางช่องเริ่มต้นและหันตามแนวทางเดิน ระบบเซนเซอร์ตั้ง odometry/yaw เริ่มต้นเป็นศูนย์ ส่วน SLAM อ้างตำแหน่งช่องจาก `map.start`
2. หยุดล้อก่อนสแกน ไม่ส่งคำสั่งหมุน chassis หรือสลับโหมดหุ่นระหว่าง Gimbal สแกน
3. **ช่องแรก:** recenter → อ่านหน้า → ซ้าย −90° → หลัง −180° → ขวา +90° → recenter กลับหน้า จากหลังไปขวาใช้ `move` คำสั่งเดียว ไม่แวะหยุดที่ซ้าย
4. **ช่องใหม่ถัดไป:** recenter → อ่านหน้า → ซ้าย −90° → ขวา +90° → recenter กลับหน้า จากซ้ายไปขวาใช้ `move(yaw=180)` คำสั่งเดียว ด้านหลังใช้ทางที่เดินผ่านแล้วเป็นหลักฐานว่าเปิด
5. รอ action จบและพักตาม `gimbal.settle_sec` แล้วรับ ToF สดตาม `slam.scan_samples` (ปัจจุบัน 3 packet) เพื่อหาระยะ median ไม่มีการหมุนปรับแก้มุมจาก feedback หลังกลับหน้า รับ ToF ใหม่อีกครั้ง
6. บันทึกกำแพง/ทางเปิด ใช้กำแพงเดิมช่วยปรับตำแหน่ง แล้ว DFS เลือกช่องใหม่หรือย้อนกลับตามเส้นทางเดิม เมื่อเข้าช่องที่สแกนไว้แล้วจะใช้ขอบแผนที่เดิมโดยไม่สแกนซ้ำ
7. ตั้ง Gimbal กลับหน้าด้วย `moveto` ครั้งเดียวก่อนหุ่นเคลื่อน เลี้ยวหุ่นและปรับ yaw เข้าหามุมเป้าหมาย รอ ToF ด้านหน้าสด แล้วเดินพร้อม Sharp Centering และ PID รักษา yaw
8. เมื่อถึงช่องใหม่ หยุดล้อและสแกนต่อ เมื่อไม่มีทางเปิดไปยังช่องที่ยังไม่สำรวจ จะจบภารกิจและหยุดที่ช่องปัจจุบัน ไม่เดินกลับช่องเริ่มต้น

ใช้ `CHASSIS_LEAD` และไม่ใช้ `suspend()` เพื่อล็อค Gimbal ระหว่างหุ่นเดินไม่มีการส่งคำสั่งปรับ Gimbal ซ้ำ

ToF ใช้ระยะที่น้อยกว่าระหว่าง raw ที่แปลงหน่วยแล้วกับ filtered เพื่อให้การหยุดไม่หน่วงตามตัวกรอง ค่า raw ที่ไกลกว่า `sensors.tof_filter.max_valid` (ปัจจุบัน 5,000 มม.) ใช้ค่ากรองล่าสุดขณะเดิน และจำกัดเป็น 5 เมตรขณะสแกนแผนที่ จึงไม่หยุดเพียงเพราะเห็นทางโล่งไกล ข้อมูลที่หายหรือระยะใกล้ผิดปกติยังถูกปฏิเสธ หากหยุดที่กำแพงตามปกติหลังเดินอย่างน้อยครึ่งช่อง จะยอมรับการมาถึงตาม `navigation.front_wall_arrival_min_fraction` การหยุดฉุกเฉินหรือพบกำแพงตั้งแต่ต้นยังไม่ถือว่าถึงช่อง

## ทดสอบ Gimbal

เมนู 8 ใช้ workflow สแกน Gimbal โดยไม่เริ่มชุดคำสั่งเดิน เริ่มต้นทดสอบ 2 รอบ: รอบแรก 4 ทิศ รอบถัดไป 3 ทิศ แสดง ToF บนหน้าจออย่างเดียว ไม่บันทึกผลหรือสร้างโฟลเดอร์ run

ตั้งจำนวนรอบและความเร็ว recenter แยกจากความเร็ว move ได้:

```yaml
gimbal:
  test_cycles: 2
  yaw_speed_dps: 180
  pitch_speed_dps: 60
  recenter_yaw_speed_dps: 300
  recenter_pitch_speed_dps: 120
```

## Calibration

เมนู 6 เลือก Sharp ซ้าย Sharp ขวา หรือ ToF แล้วกรอกระยะอ้างอิงเพื่อเก็บตัวอย่างลง `data/calibration_measurements.csv` พอร์ตและจำนวนตัวอย่างอ่านจาก settings

พิมพ์ `q` ในช่องรับระยะเพื่อกลับเมนู Calibration โดยยังเชื่อมต่อหุ่นอยู่ ตัวอย่างที่บันทึกแล้วคงอยู่ เมื่อเก็บครบจำนวนตัวอย่างจะกลับเมนูเช่นกัน เลือกคำนวณสมการเพื่อใช้ข้อมูลที่เก็บไว้ ผลลัพธ์อยู่ใน `calibration_output/` มี `calibration.json` และกราฟของเซนเซอร์ที่มีข้อมูล

เลือก 0 ในเมนู Calibration เพื่อออกและปิด connection การคำนวณสมการอย่างเดียวไม่ต้องเชื่อมต่อหุ่น

## ไฟล์ผลลัพธ์

แต่ละรอบสำรวจเก็บข้อมูลใน `telemetry_logs/runN/` ที่เดียว:

| ไฟล์ | เนื้อหา |
| --- | --- |
| `map.png` | แผนที่ พิกัด `(row, column)` หมายเลข step และเวลารวมเป็นนาที/วินาที |
| `actions.html` | รายการก้าว การเดิน เลี้ยว สแกน และรายละเอียดเซนเซอร์ เปิดใน browser ได้ |
| `runN_TIMESTAMP_map.json` | แผนที่ เหตุการณ์ เส้นทาง และสถานะการสำรวจ |
| `runN_TIMESTAMP.json` | ข้อมูลเซนเซอร์และระยะเวลารัน |
| `runN_TIMESTAMP.csv` | ข้อมูลเซนเซอร์รายตัวอย่างในรูปแบบ CSV |
| `events.csv` | เหตุการณ์ระหว่างสำรวจ พร้อมรายละเอียดแต่ละ action |
| `runN_TIMESTAMP_plot.png` | กราฟวิเคราะห์เซนเซอร์ |

เวลาบน `map.png` มาจาก `duration_sec` ของ telemetry ของรอบนั้น รวมเวลาตั้งแต่เริ่ม recorder ไม่ใช่เฉพาะเวลาที่หุ่นเดิน บันทึกทั้ง JSON และ CSV เพื่อให้อ่าน log ในโปรแกรมและตารางได้ โดยไม่สร้างสำเนาแผนที่ใน `data/`

งานทดสอบเดิน/เลี้ยว/ชุดคำสั่งบันทึก telemetry และกราฟ ส่วนเมนูดูเซนเซอร์สดกับทดสอบ Gimbal ไม่บันทึกผล เมนู 7 ใช้วิเคราะห์ run ที่บันทึกไว้

`completed` หมายถึงสำรวจครบทุกช่องที่เข้าถึงได้และหยุดอยู่ที่ช่องสุดท้าย ไม่รวมช่องปิดที่เข้าไม่ได้ หากถูกหยุด เกิดข้อผิดพลาด หรือถึงขีดจำกัดภารกิจ จะเก็บแผนที่บางส่วนพร้อมสถานะของรอบนั้น

## ขอบเขตและการตรวจงาน

เป็น Grid-constrained SLAM สำหรับกำแพงตามแนวช่องและสนามคงที่ ไม่ได้ทำ pose graph หรือ relocalization แบบอิสระ ความคลาด odometry มุม Gimbal และการมองเห็นกำแพงมีผลต่อความแม่นยำ

ไม่มีโฟลเดอร์ tests การยืนยันการเดิน สแกน Centering และกันชนใช้หุ่นจริงและอ่าน telemetry โดยใช้เมนูทดสอบ Gimbal เดินหนึ่งช่อง และเลี้ยวประกอบการตรวจสนาม
